Entraide / Backend & Auth / Question #9841

Comment gérer le rafraîchissement transparent des JWT tokens sous Next.js 14 App Router avec FastAPI ?

Résolue
Moussa Traoré (@moussa) • Bamako, Mali • il y a 3h

Bonjour à tous, j'ai une application où le JWT expire après 15 minutes. Lorsque l'access token expire, je veux que le middleware Next.js intercepte l'appel, utilise le refresh token stocké en cookie HttpOnly pour obtenir un nouveau token auprès de FastAPI, puis poursuive la requête initiale sans déconnecter l'utilisateur.

middleware.ts typescript 
// middleware.ts - Boucle infinie actuelle
export async function middleware(request: NextRequest) {
  const token = request.cookies.get('access_token')?.value;
  if (!token) {
    const res = await fetch('https://api.monsite.com/auth/refresh', { method: 'POST' });
    // Bloqué ici en cas de token déjà expiré...
  }
}
Solution Validée par l'Auteur de la Question (Moussa T.)
+50 pts entraide
Amadou Diallo (@amadou)
Dakar • Senior Contributor

Voici le pattern que nous utilisons en production sur les applications fintech. Il ne faut pas appeler l'API de refresh directement dans le Edge Middleware s'il manipule des cookies sécurisés. Il est préférable d'utiliser un Route Handler intermédiaire avec mutex de verrouillage :

app/api/auth/refresh/route.ts typescript 
// app/api/auth/refresh/route.ts
import { cookies } from 'next/headers';
import { NextResponse } from 'next/server';

export async function POST() {
  const cookieStore = cookies();
  const refreshToken = cookieStore.get('refresh_token')?.value;
  if (!refreshToken) return NextResponse.json({ error: 'No token' }, { status: 401 });

  const backendRes = await fetch(`${process.env.BACKEND_URL}/auth/refresh`, {
    method: 'POST',
    headers: { 'Authorization': `Bearer ${refreshToken}` }
  });
  const data = await backendRes.json();
  const res = NextResponse.json({ ok: true });
  res.cookies.set('access_token', data.access_token, { httpOnly: true, secure: true });
  return res;
}
